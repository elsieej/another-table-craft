# CSV export: defaults

`exportSelectedRowsCsv(table)` needs no configuration at all — check some rows, click export, get a real
`.csv` file download of exactly what you selected.

<CsvExportDefaultsExample />

Check a few rows and click **Export CSV** — your browser downloads `table-export.csv` containing exactly
those rows. This calls the real, published `exportSelectedRowsCsv`, not a mock.

```tsx
import { exportSelectedRowsCsv } from 'another-table-craft'

;<button onClick={() => exportSelectedRowsCsv(table)} disabled={selectedCount === 0}>
  Export CSV
</button>
```

## What the default export includes

- **Rows**: only currently-**selected** rows (`table.getSelectedRowModel()`). If nothing is selected, the call
  is a no-op — no empty file, no error.
- **Columns**: every visible column _except_ `select` and `actions` (matched by column id) — so a checkbox
  column like the one above never ends up as a literal "true"/"false" column in your CSV.
- **Headers**: the column's own `header` string, if it's a plain string (as all three data columns here are);
  otherwise the column's id.
- **Empty values**: a cell whose resolved value is `undefined`, `null`, or `''` is omitted from that row's CSV
  entry entirely, rather than written out as an empty field.
- **Filename**: `table-export.csv`.

Of these, only the filename and which extra columns get ignored are actually configurable (via
`createCsvConfig`'s `fileName` and `ignoredCols`, covered in its own showcase) — `select`/`actions` always stay
ignored, and which rows get exported, which header a column shows, and the empty-value rule are all fixed
behavior, not options.
